**关键结论（可直接引用）**

1. **规则基线的失效点是品类迁移，不是数据量**：同品类 F1 0.8108 / 新品类 0.5439。召回 0.71→0.46、精度 0.94→0.67，两头都掉。

## 3. 关键约束

**技术栈**：Python 3.13 + FastAPI + SQLite（原生 sqlite3，无 ORM）；pytest；Docker（非 root + 探针）；无前端框架。

**纪律（不可放宽）**

- 参数状态只有 `draft` / `verified`；`verified` 必须有 来源 + 生效日期 + 核实日期，写在 `CHECK` 里。
- 查不到就保持 draft，**禁止「大概 15%」这类印象值**。填错的数比没有数危险。
- 每个指标对应一条命令，默认 `make check`（EXIT=0 才算过）。
- 新增业务表必须同步 `tests/test_migrations.py` 的 `BUSINESS_TABLES`，且 `db.py roundtrip` 指纹一致。
- 表级 `CHECK` 不能跨行查询，区间重叠只能靠 `audit()` 检出，不许假装数据库能拦。
- 158 条新增抽取样本 + 77 簇聚类标注**未经人工复核前，对外不得称「人工标注」**。
- 不爬亚马逊前台；只采信官方站点（Seller Central / USITC / CBP）。

**表述风格**：结论先行 + 表格对比；每个决策给「为什么这么选 / 为什么不选另一种」；不伪造输出（例如 README 里 docker 段保留 11-19 的 v8 原文并加时点说明）。

### 6.1 表结构（`m0009_fba_schedule.py`，逐字）

```sql
CREATE TABLE fba_fee_schedule (
    id                  INTEGER PRIMARY KEY,
    marketplace         TEXT NOT NULL,
    size_tier           TEXT NOT NULL
                        CHECK (size_tier IN (
                            'small_standard', 'large_standard',
                            'large_bulky', 'extra_large'
                        )),
    weight_min_oz       REAL NOT NULL CHECK (weight_min_oz >= 0),
    weight_max_oz       REAL CHECK (weight_max_oz IS NULL OR weight_max_oz >= 0),
    price_band          TEXT NOT NULL
                        CHECK (price_band IN ('under_10', '10_to_50', 'over_50')),
    season              TEXT NOT NULL
                        CHECK (season IN ('off_peak', 'peak')),
    base_fee_usd        REAL NOT NULL CHECK (base_fee_usd >= 0),
    per_increment_usd   REAL NOT NULL DEFAULT 0 CHECK (per_increment_usd >= 0),
    increment_oz        REAL CHECK (increment_oz IS NULL OR increment_oz > 0),
    included_oz         REAL CHECK (included_oz IS NULL OR included_oz >= 0),
    source_url          TEXT,
    effective_date      TEXT,
    verified_at         TEXT,
    status              TEXT NOT NULL DEFAULT 'draft'
                        CHECK (status IN ('draft', 'verified')),
    note                TEXT,
    created_at          TEXT NOT NULL,
    -- 同一维度组合下，同一个重量起点只能有一行。这拦不住区间重叠
    -- （[0,4) 与 [2,6) 的起点不同、依然重叠），重叠检测只能在写入路径
    -- 与 audit() 里做——SQLite 的 CHECK 不能跨行查询。这是本表已知边界。
    UNIQUE (marketplace, size_tier, price_band, season, weight_min_oz),
    CHECK (weight_max_oz IS NULL OR weight_max_oz > weight_min_oz),
    -- 有增量单价就必须说明「每多少 oz 加一次」，否则计价函数无法收敛；
    -- 没有增量单价则 increment_oz 必须为空，避免留下语义含糊的半行。
    CHECK (per_increment_usd = 0 OR increment_oz IS NOT NULL),
    CHECK (per_increment_usd > 0 OR increment_oz IS NULL),
    CHECK (
        status <> 'verified' OR (
            source_url IS NOT NULL
            AND effective_date IS NOT NULL
            AND verified_at IS NOT NULL
        )
    )
);

CREATE INDEX idx_fba_lookup ON fba_fee_schedule
    (marketplace, size_tier, price_band, season, weight_min_oz);
```

注意 `UNIQUE` 里**没有** `product_class` 和版本维——这正是 m0010 要解决的问题。

def pick_row(rows, *, size_tier, weight_oz, price_band, season) -> FeeRow | None:
    """在四维约束下挑一行。多个候选时取 weight_min_oz 最大者。
    只在这四个维度上比对，从不「降到相邻尺寸段去找」。
    返回 None 表示表里真的没有这一格。"""

def quote(rows, *, size_tier, selling_price, ship_date,
          weight_oz=None, weight_lb=None,
          fuel_surcharge_rate=None) -> FbaQuote:
    """fuel_surcharge_rate=None 表示「本次没有可核实的附加费率」，
    按 0 计提，但在 assumptions 里显式记一笔——

### 7.3 新增的三条结论（可直接引用）

1. **「时段」不是「费率期」**：2026 旺季一直算到 2027-01-14，而 2027 旺季官方未发布。
   只有 `season='peak'` 时，2027-12-01 的报价会静默命中 2026 旺季行——用过期表算出正常数字。
   版本表是解这个问题的唯一办法，`effective_date` 存在但不参与判断等于没有。
2. **产品类别差 18.8–25.9%**：同一档 `large_standard` · 8–12 oz · $10–50，非服装 $4.20 /
   危险品 $4.99（2026 非旺季）。按非服装给含锂电池的扫地机报价，每件少算约 $1.16（旺季）。
3. **2027 低价 FBA 资格收窄命中本品类**：紧凑型家电等不再享 `<$10` 档。`quote()` 在
   「2027 期 + `under_10`」时发 warning——这不是脚注，是报价可能偏低 $0.6–1.0 的地方。
