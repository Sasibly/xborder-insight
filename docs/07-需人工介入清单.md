# 需人工介入清单

> 用途：把「系统算不出来」与「我查不到」分开记账。
> 每一条都写明**为什么只能由人做**、**具体动作**、**给我的产出格式**、**不做的后果**。
> 生成：2026-11-21 ｜ 维护约定：新增项给 `H` 编号，已完成的划掉但保留编号，不重排。

## 为什么需要这份清单

这个项目有一批数字，代码里没有默认值，查不到就抛 503。这是有意的设计——
但「抛错」只能说明缺什么，不能说明**该由谁去补**。缺的东西分两类：

- **我能查的**：官方费率页、法规原文、税率库。我自己去抓，抓不到就说明抓不到。
- **只有你能给的**：登录态后台里的数据、你产品的物理事实、你的经营数据、
  以及「这样算对不对」的业务判断。

第二类如果只写一句「需要你确认」，实际上等于没交付——因为你还得自己搞清
要确认什么、去哪儿看、看到什么算数。所以这份清单的验收标准是：
**每一项都能让你在不知道项目内部细节的情况下，照着做一次。**

## A 级：不做则利润模型给不出任何结论

这三项的共性是——它们不是「来源难找」，而是**答案在你的后台或你的产品上**，
任何公开页面都不会写。

### H1 · 佣金类目归属（15% 还是 8%）

| 项 | 内容 |
| --- | --- |
| 为什么只能你做 | 官方脚注写明「A product's fee category may not be the same as the category that appears to customers」。归属由 ASIN 级数据决定，必须登录后台查 |
| 具体动作 | 卖家后台 → **Reports → Fulfillment → Fee Preview**（报告名以此为准，菜单文案可能不同）。下载后找到你目标 ASIN 那一行，看 **`Product category`** 和 **`Referral fee rate`** 两列 |
| 也可以 | 库存管理页搜该 ASIN，看 **Fee Preview** 列，点 **Estimate fee** 弹窗，里面有 fee category 明细 |
| 给我的产出 | 三样：①ASIN ②后台显示的 fee category 原文 ③该 ASIN 的 referral fee 百分比。截图或复制文字都行 |
| 不做的后果 | $29.99 的商品，15% 与 8% 差 **$2.10/件**，足以把「勉强可做」翻成「明显可做」。填错方向不会报错 |
| 影响面 | `cost_params.amazon.referral_rate` 一项，但它是毛利里最大的单项费用之一 |

> 如果目标品类确实跨两个 fee category，就给我两条，我把 `applies_min/max` 按类目分开登记——
> 这比硬选一个诚实。

### H2 · 产品物理参数（决定 FBA 档位）

**11-21 已按市场典型规格预填一遍，先把「要不要测」问清楚。**

用 6 个品类各两台在售机型的公开包装规格跑了一遍（画像 `data/profiles/market_typical.json`，
命令 `python scripts/db.py fba-profile`，状态 `assumed` 非实测）。结果不是「差几个点」，
而是**这批家电普遍卡在 18×14×8 之外**：

| 品类 | 典型包装（英寸） | 判定 | 要不要你测 |
| --- | --- | --- | --- |
| 空气净化器 | 10.2×10.2×15.4 / 7.28×14.56×11.22 | 两台结论**相反**（一台超 27.5%、一台余 9.0%） | **要**，按你那台的箱子量 |
| 咖啡机 | 14.17×14.17×7.87 | 次长边超 **1.2%**（14.17 vs 14） | **要**，先量这一台——翻转即变成可报价 |
| 电热水壶 | 9.45×8.27×9.45 | 最短边超 **3.4%**（8.27 vs 8） | **要**，差得极少，必须实测 |
| 宠物饮水机 | 13×6.5×7.875 | 在标准内（余 18.8%） | 尺寸不用；**要确认含不含锂电池** |
| 扫地机器人 | 13.39×5.51×14.92 | 单机勉强过（次长边余 4.4%），**带基站必超** | **要**，且先确认有没有基站 |
| 无线充电器 | 5×4.2×2 | 在标准内，裕度 70% | 不用 |

所以 H2 的实际工作量从「6 个 SKU 各填 4 列」变成三件事：

1. **量 4 台箱子**（净化器 / 咖啡机 / 水壶 / 扫地机）——长×宽×高（英寸）+ 包装后实重（oz）；
2. **确认 1 个含锂**（宠物饮水机：同品类既有无线泵带 48 h 备份电池的款，也有纯插电款，
   两者费率差近两成）；
3. **无线充电器可以直接报价**，不用动。

> 为什么不是「按典型规格直接出结论」：典型规格是**品类推断单品**，不是你的 SKU。
> 净化器两台机型一个超 27.5% 一个余 9.0%——取平均会得到一个纯粹虚构的「差不多」。
> 这类分歧只能靠实测消除，不能靠更用力的估计。见 `docs/04` 第 12 节。

**以下是原来的四列口径，实测时照这个填。**

不需要一次给全。给一个上界，多数品就能定论。

| 级别 | 你要给的 | 我能做到 | 大约耗时 |
| --- | --- | --- | --- |
| **A 级（先给这个）** | 每个 SKU 一行四列：`含锂电池 是/否` · `包装后实重上界` · `能否装进 18×14×8` · `包装体积大致上界` | 用官方费率表算出 FBA 费区间，**区间整体在阈值一侧时直接出 GO / NO-GO** | 每 SKU 1–2 分钟（看供应商规格书 / 拿现有包装比一下） |
| **B 级（要精确报价时）** | 包装后 长×宽×高（英寸）+ 实重（oz） | 查到唯一一格，给出单一 FBA 费与精确毛利 | 每 SKU 5 分钟（要实际称重量方） |

四列的判定口径（照这个填，别自己换算法）：

| 列 | 怎么判 | 填错的后果 |
| --- | --- | --- |
| 含锂电池 | 产品本身或包装内是否含**锂离子 / 锂金属 / 锂聚合物**电池。含 → 危险品费率表；不含 → 普货表 | 含锂按普货填，每件少算约 $1.16，响应里看不出来 |
| 实重上界 | 包装后总重（含外箱与填充）。可以给上界，不必精确 | 给裸机重量会判小一档，费率低 $0.5–1 |
| 能否装进 18×14×8 | **三条同时满足**才算：最长边 ≤18、次长边 ≤14、最短边 ≤8（英寸） | 任一条超出就落进大件/超大件，那两段费率未录，只能返回 503 |
| 包装体积上界 | 长×宽×高（英寸³）的粗略上限。不知道就写「一个鞋盒 ≈ 400」 | **这一列最容易漏。** 只填「装得进」而不填体积，费用上界按 14.5 lb 算，很多品会判不了 |

| 项 | 内容 |
| --- | --- |
| 为什么只能你做 | 尺寸段与重量档是**产品事实**。用裸机尺寸会被判小一档，费率低 $0.5–1；用错档不报错。是否含锂电池同样只有你知道（BOM 决定），猜成非服装每件少算约 $1.16 |
| 具体命令 | 先看要不要测：`python scripts/db.py fba-profile`；A 级：`python scripts/db.py fba-envelope --lithium yes --unit-lb 2 --fits-standard --max-volume-in3 400 --price 59.99 --ship-date 2026-11-21`；B 级：把 `--fits-standard --max-volume-in3 400` 换成 `--dims 12x10x6` |
| 给我的产出 | 一张 `SKU / 含锂电池 / 实重上界 / 能否装进 18×14×8 / 体积上界` 的表；B 级再把后两列换成三边尺寸 |
| 不做的后果 | A 级不做 → 决策结论只能是 `NEED_MORE_INFO`（不是 NO-GO，也不是 GO）。**注意：不会退化成按 0 计**——`fba_fee` 默认 0 的老路已在 11-21 封掉，缺 FBA 会 422 |
| 影响面 | FBA 费、尺寸段判定、`size_fit` 类标签的解读 |

> **为什么 A 级就够用**：FBA 费区间的两端都是官方费率，不是估计值。若「按最贵档算毛利率仍 ≥ 15%」，
> 真实值只会更好，可以直接 GO；若「按最便宜档算仍 < 15%」，换档位救不回来，直接 NO-GO。
> 只有区间跨过阈值的那部分 SKU，才必须升到 B 级去量箱子。
>
> 实测（售价 $59.99、危险品、实重 ≤2 lb、2026 旺季、报价 $18、佣金 15%）：
>
> | 你给到哪一步 | 毛利率区间 | 能不能定论 |
> | --- | --- | --- |
> | 只给「装得进 18×14×8」 | 12.9% – 24.9% | 判不了（跨 15%） |
> | 再加「体积 ≤400 in³」 | 20.0% – 24.9% | 可判：毛利项通过 |
> | 换成精确三边 12×10×6 | 20.0% – 24.9% | 同上，且能直接给点位 |
>
> 结论：**A 级的第四列不是可选项**。只回答前三列时，很多品会停在「判不了」，
> 而多填一个体积上界通常只需要看一眼箱子。

### H3 · 四项经营数据（无官方来源）

这四项**不存在**「官方正确值」，只有你的实际数据或明确的假设值。这一栏的关键不是
数值本身，而是**它被谁认领**。

| 参数 | 具体动作 | 产出格式 | 不给的后果 |
| --- | --- | --- | --- |
| `logistics.inbound_freight` 头程 | 找出最近一次货代报价单，或按 `总运费 ÷ 总件数` 算单件分摊 | `$X.XX / 件` + 报价单编号或日期 | 落地成本缺一块，毛利虚高 |
| `returns.rate` 退货率 | 卖家后台 → **Reports → Fulfillment → FBA Customer Returns**，取近 90 天 `退货件数 ÷ 发货件数` | `X.X%`（注明统计区间） | 高退货品类会被判成「可做」 |
| `returns.handling_fee` 退货处理费 | 退货仓/翻新商报价；或按「退回运费 + 检测费」估 | `$X.XX / 件`，或明确写「按 $X 假设」 | 退货成本低估 |
| `ads.acos_benchmark` | 你的品类历史 ACOS；没有就明确说「无数据，按行业假设 30%」 | `X%` + 来源 | 盈亏平衡 ACOS 无处对照 |

**这一栏的规矩**：给不出真实值时，明确说「这是假设」也可以——我会把它写进
`note` 并让响应回显 `data_provenance: assumption`。**但不能留空让我猜**。
留空的话系统会抛 503，比猜错好，但项目就停在这里。

### H8 · 关税的申报口径

| 项 | 内容 |
| --- | --- |
| 为什么只能你做 | 「是否中国原产」「申报价值是否含运费保险」是贸易事实，不是法规事实 |

| # | 事项 | 你需要回答的 |

| H9 | 是否做卖家访谈 | 做 / 不做。不做我就把 README 的「需求来源」固定写「基于公开资料推演」，不虚构 |
