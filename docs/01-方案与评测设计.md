# 跨境选品决策引擎 · 方案与评测设计

> 一句话定位：把竞品评论区里的非结构化抱怨，转成可排序、可溯源、可评测的选品机会清单。

## 1. 为什么是这个选题

简历上同类项目普遍长这样：搭一个电商站，接一个 RAG 问答。前者是教程项目，后者与「法律智能问答」同质化。本项目的差异点在于：

| 维度 | 法律智能问答（已有） | 本项目 |
| --- | --- | --- |
| 核心任务 | 检索 + 生成 + 溯源 | 抽取 + 归并 + 排序 |
| 知识来源 | 结构化知识库 | 无知识库，全靠现场抽取 |
| 最难的环节 | 召回率 | 输出格式的稳定性与可评测性 |
| 模型角色 | 答案生成器 | 信息抽取器（可被程序校验） |

两个项目合起来，覆盖「知识增强生成」与「非结构化信息结构化」两类主流落地场景，避免被判定为只会调 API。

## 2. 业务闭环

```
竞品评论(JSONL) → 清洗去重/语言识别 → 单条结构化抽取(LLM)
   → 证据短语向量聚类 → 主题归并 → 机会分排序 → 决策看板/JSON
```

输出物是「机会主题」列表，每个主题包含：提及次数、负面占比、机会分、代表性证据原文、建议改进方向。

机会分定义（可解释、可复现，不用黑盒）：

```
opportunity = 0.55 * mention_norm + 0.35 * negative_ratio + 0.10 * severity_norm
```

- `mention_norm`：该主题被提及次数在全部主题中的归一化排名（需求广度）
- `negative_ratio`：该主题中负向情绪占比（痛点严重度）
- `severity_norm`：抽取置信度均值（证据强度）

刻意不用「LLM 直接打 0-100 分」，因为不可复现、无法解释、面试必被追问。

## 3. 关键设计决策

| 决策 | 选择 | 理由（面试要能讲出来） |
| --- | --- | --- |
| Web 框架 | FastAPI | Pydantic 与结构化输出天然同构，校验即契约；异步适配批量 LLM 调用 |
| 输出契约 | Pydantic 强类型 + JSON Schema | 让模型输出成为「可校验的数据」而非「一段文本」，是可靠性的前提 |
| 校验失败处理 | 三级降级：修复解析 → 重试 → 标记 `unparsed` 并计入指标 | 不静默丢弃，失败率本身是指标的一部分 |
| 聚类 | 自实现余弦相似度 + 贪心合并 | 数据量在千级，无需引入 sklearn/faiss；且相似度阈值可解释、可调 |
| 不做向量数据库 | 否 | 主题数在几十量级，内存计算足够；引入向量库属于过度设计 |
| 不引入 Celery/Redis | 否 | 单机异步 + 信号量并发足够；把「为什么不用」写清楚比硬上更有说服力 |
| 金额/成本 | 记录每次调用的 token 与耗时 | 成本与延迟必须是可量化指标，否则简历数字无从谈起 |

## 4. 评测方案

### 4.1 数据集

- `data/samples/reviews_sample.jsonl`：2 个品类（无线充电器、宠物饮水机）共 40 条中英混合评论，人工构造，规避平台数据合规问题
- `data/eval/gold_labels.jsonl`：对上述评论逐条标注痛点标签（多标签），标签来自 10 类预定义 taxonomy

数据来源在 README 中明确声明为「人工构造的合成样本，不来自任何平台抓取」，这既是合规底线，也是面试加分项。

### 4.2 指标

| 层级 | 指标 | 说明 |
| --- | --- | --- |
| 抽取层 | Precision / Recall / F1 | 逐条评论对比 gold 标签集合，micro 平均 |
| 稳定性 | 解析成功率 | `成功解析条数 / 总条数`，含重试后成功 |
| 主题层 | 主题覆盖率 | 被正确归并到某主题的标签占比 |
| 工程 | P50 / P95 延迟、单条成本 | 每条评论的平均耗时与 token 成本 |

### 4.3 基线

Mock 模式（规则抽取）作为下限基线，Live 模式（LLM 抽取）与之对比。**两个数字都会写进 README**，这比只报一个好数字更可信。

## 5. 简历写法（STAR + 可量化）

> **跨境选品决策引擎**（个人项目，独立完成）
> - 背景：跨境卖家选品依赖人工翻评论区，痛点发现效率低且主观。
> - 方案：设计「抽取 → 聚类 → 排序」三段式管道，用 Pydantic 契约约束 LLM 输出，实现三级降级解析，解析成功率从 X% 提升至 Y%。
> - 工程：FastAPI + 异步并发调度，接入百炼 qwen，单条评论平均耗时 X 秒、成本 ¥X；自实现余弦聚类替代向量库，降低部署复杂度。
> - 评测：人工标注 N 条评论构建 gold set，抽取 F1 = X，主题覆盖率 X%；机会分采用三项加权公式，保证排序结果可解释可复现。

**数字填写规则**：所有 `X` 必须来自 `scripts/demo.py` 与 `scripts/run_eval.py` 的真实输出，面试前跑一遍并把结果抄进简历。禁止估算。

## 6. 明确不做的事

- 不做全量电商站（商品/购物车/支付）：与选题价值无关，且是教程项目信号
- 不爬取平台前台数据：违反平台条款，且会被质疑工程判断
- 不做模型微调：本任务瓶颈在输出契约与评测，不在模型能力
- 不做多租户与权限体系：对简历岗位无增信作用
