# 项目长期约定 · 跨境选品决策引擎

## 输出与协作约定（用户明确要求）

- **需要数值时直接给单值**（2026-11-23 17:13 新增，优先级最高）：给价格 / 数量 / 阈值时
  直接判断并给出最合适的那个数，**不给范围、不反复追问**。信息不足先说明必要假设，
  再给数值，数值后标「**由助手给定值**」。
  落地：`docs/04` §27 单值总表 + `tests/test_single_values.py` 逐条钉住，
  含两个「看起来正好」的陷阱——咖啡机 $14.90 = 14.99%（不过线，签字线只能 $14.89）、
  净化器 $24.50 = 14.76%（「再让一档」的心理价，已掉出线）。
  取整优先：净化器最高可付报 **$24.30** 而不是精确解 $24.33——少 3 分换「听起来像我的顶」。
- **任务分解必须具体到可执行动作**，不接受「需要你确认」「请你补充数据」这类笼统说法。
  每一项要给：为什么只能你做 / 具体去哪儿看（报告名、字段名） / 给我什么格式 / 不做的后果。
- **需人工介入的台账固定在 `docs/07-需人工介入清单.md`**，编号 `H1…Hn`（H = Human）。
  新增项追加编号，完成的划掉但保留编号，不重排。提到人工依赖时引用编号，不重新描述。
- 结论先行 + 表格对比；每个决策给「为什么这么选 / 为什么不选另一种」。
- 数字必须可复现：每个指标对应一条命令，默认 `make check`。

## 数据纪律（不可放宽）

- 参数状态只有 `draft` / `verified`；`verified` 必须有 来源 + 生效日期 + 核实日期，写在 CHECK 里。
- 查不到就保持 draft，**禁止用「大概 15%」这类印象值**。填错的数比没有数危险。
- 缺失 ≠ 通过：合规规则未覆盖或未核实一律 `unknown`，不得降级成 `clear`。
- 158 条新增抽取样本 + 77 簇聚类标注**未经人工复核前，对外不得称「人工标注」**。
- **AI 设定值必须标「设定」不标「核实」**：用户授权代填的数一律保持 `draft`，
  文档里写明「AI 设定 / 非核实 + 依据」，并给出替换条件（哪一页一读就能定死）。
  已按此处理：退货率 12.6%、回价 净化器 $28.60 / 咖啡机 $16.80（`docs/04` §24）。
- 不爬亚马逊前台；只采信官方站点（Seller Central / USITC / CBP）。

  用 `PYTEST_ADDOPTS="--basetemp=/tmp/pytest-xbi"`，不改仓库。

## 退货率压测与谈判锚（2026-11-23 16:55）

- **判定规则进代码**：两档都为正才谈（`admission.stress_test`，CLI `--stress-returns`）。
  门槛取 0 不取 15%——基线不达标才需要谈价，门槛定 15% 会把所有候选挡在门外。
- **逐 SKU 退货率不落库**：`cost_params` 只有全局 `returns` 一行，现在只能靠命令行传，
  对 API 与 `make check` 不生效。要生效得加 `product_returns` 表，未做（别以为已经进库了）。
- **FOB 公允参考价是内部锚**：只用来判断对方报价离不离谱，**绝不对供应商说出口**。
  开口价 = max(20% 线, 公允 × 0.85)——低于公允 15% 以上的报价不会被当回事。
  20% 线单独用会给出「没人理的开价」（净化器 $20.89 = 公允 −25.4%）。
- **两台分道**：净化器谈价 + 锁箱规（$24.00 基线 15.49%）；咖啡机只谈箱规（压测转负，
  且报价已低于公允）。别再把「咖啡机 $14.50」挂嘴边——那比公允低 27.5%。
- 咖啡机 FOB 带位未定（`H23`）：$15–19 与 $18–22 给出相反结论；「先要箱规」在两版都成立。

## 箱规：安全垫 ≠ 档位上限（2026-11-23 17:10，犯过一次）

- **大号标准件上限是 18×14×8**（`package.STANDARD_MAX_DIMS_IN`），不是谈判目标 17.5×13.7×7.5。
  现行净化器彩盒 17.52×13.78×7.48 / 9.26 lb 本就在限内 → FBA $11.35。
  我要求供应商「改到 17.5×13.7×7.5」被拒（要换纸板规格），但这句话对 FBA **零影响**。
- **对供应商只说外部事实**（18×14×8 是平台上限、超档多少钱），不说内部保守值。
  内部安全垫（0.22 英寸余量）是给自己定价用的，当外部要求提必然被拒——那个值对他是真成本、对我是零收益。
- 按上限改成**条款**而不是要求：`三边按样品 X 执行且不超 18×14×8，超档差额供方承担`。
  他现在的箱子就满足 → 零成本承诺。
- **提外部诉求前先查 `measured_skus.json` 的 `superseded` 段和 docs 里的过期条目。**
  净化器 24×15×15 / 18.5 lb 早在 11-23 13:51 被五项分解推翻（箱体积是机器的 4.84 倍、
  毛重 ≠ 净重 + 空箱）；`docs/07`「5400 in³ 改包不可能」是它的残留，17:10 已改。
- 掉档代价：次长边 13.78 → 14.01 即进 small_bulky，$11.35 → $14.00，
  $24.33 从 15.01% → 11.69%（$2.65/件、3.32 点）。`tests/test_purifier_box.py` 9 条钉住。

## 结构现状（易忘）

- 迁移已到 **v12**；`db.py roundtrip` 是「up→down→up 指纹一致」的硬门槛。
  改 CHECK 只能重建表，且必须按 m0010 的手法「先改名挪走、再逐字建表」——
  直接 CREATE+rename 会让 sqlite_master 的 DDL 带双引号，指纹与未升级库对不上。
- 新增业务表必须同步 `tests/test_migrations.py` 的 `BUSINESS_TABLES`（现含 `fba_rate_version`）。
- 表级 `CHECK` **不能跨行查询**，所以区间重叠只能靠 `audit()` 检出，别假装数据库能拦。
- FBA 费率已版本化（m0010/m0011）：`fba_rate_version`（生效区间）+ `fba_fee_schedule`
  （version_key / size_tier / product_class / weight / price_band）。行上**不再存** season 与
  effective_date——版本是唯一真相源，别再往行上加回冗余字段。
- `product_class` 与 `size_tier` 一样没有默认值：官方三套表差 18.8–25.9%，猜错静默低估 $1.16/件。
- 费率期不按年份切（2026 旺季算到 2027-01-14，2027 旺季官方未发布）。判断「哪一期」只能按
  发货日期落在哪个版本的闭区间，不能按 `season` 或年份字面值。
- **`CostProfileInput.fba_fee` 没有默认值 0**（c4f1d07 封掉）。缺它就必须给
  `product_class` + `ship_date`，否则 422；服务层据此调 `fba_db.envelope()` 算区间。
  别再给 FBA 类字段加「中性默认值」——不填被当成 0 等于静默高出 10 个点毛利。
- 未知 FBA 时是**三值判断**，不是二值：乐观端不达标 → FAIL；保守端达标 → PASS；
  跨阈值 → `NEED_MORE_INFO`。点值永远取最贵档（低估成本不可逆）。
  只有跨阈值的 SKU 才需要真实尺寸重量，H2 已降级为「先给重量上界」。
- 包络宽不是缺陷：宽是因为真的不知道。用假数把它变窄才是缺陷。
- 有实测值就用 `--exact-weight` 把区间收成单点；默认口径下端永远从 1 lb 起算
  （表示「不确定会不会更轻」），两者上界相同。**计费重量 = max(实重,体积重) 向上取整**，
  不是实重——净化器实重 18.5 lb / 计费 39 lb，差 $10.45。
- 大件含锂 = **+$1.28/件常数**（危险品−普货 $1.24 × 1.035 燃油），不随重量变；
  价格带在大件上只差 $0.80，在标准尺寸上会换整张表。
- 典型规格推断 **不能用于判定尺寸段**：实测咖啡机超 18.75%、水壶超 5.0%，
  而按典型规格估的是 1.2% / 3.4%。量包装，不量裸机。
- 净化器 5400 in³、扫地机 5544 in³，标准尺寸上限仅 2016 in³（18×14×8）→ 改包不可能。
- 画像分两档、两个文件：`market_typical.json`(assumed，永不可升级) 与
  `measured_skus.json`(measured)。**status 是文件级**，不混装。measured 档强制
  evidence + 每行 measured_at + battery_confirmed，并自动 `exact_weight`。
- 含锂未核过的行**同时显示两套费率表**；扫地机取含锂（$25.51），早先的 $24.23 用错了口径。
- 运输维（domain/transport.py）：电池形态 built_in(PI967)/removable(PI966)/standalone(PI965)
  必须显式，**未确认时不给 ok**。need_info 只在「结论会翻转」时用（空运：可客机↔禁运）；
  只是文件多少变时取最严档（海运）。PI 条款与 100Wh 门槛仍是 draft，不写时效与单价。
## 包装事实 → FBA（2026-11-21，domain/package.py）

- 三条判定写在代码里，不是文档里：含锂电池 → 危险品表（无默认值）；小号标准件 16 oz
  按单位重量、大号标准件 20 lb 取 max(实重, 体积重)；18×14×8 三条边同时满足才是标准尺寸。
- 体积重 = L×W×H÷139（英寸→磅），除数写死。**计费重量不是实重**：
  实重 2 lb + 18×14×8 → 232 oz → 费用上界差 $5.11。
- **「装得进 18×14×8」是排除项，不是收窄项**。它只排除大件，标准尺寸内部体积重仍按
  14.5 lb 算。收窄必须给 `--dims` 或 `--max-volume-in3`（体积与体积重线性，一个数就够）。
- **只有实重能推出大号标准件**：18×14×8 装满体积重 14.5 lb < 20 lb，大件判定只看三边。
- 实重按上界用，区间下端仍从最轻档起算。别为了让区间好看把它当精确值。
- 小号标准件三边上限 = 15×12×0.75 英寸（官方 Product size tiers 页，2026 定义表原文，
  11-21 核实，H13 已关闭）。三边给全时改单值判定；只有「≤16 oz 但没给三边」保留两段。
  15×12×0.75 装满体积重仅 15.5 oz < 16，不存在「实重达标但体积重顶出小号」。
- 4/6 品类（净化器/咖啡机/水壶/带基站扫地机）按官方定义全落 **small_bulky**
  （≤50 lb / 37×28×20 / 长+围 ≤130）。11-21 已补录 2026 两期（m0012，24 行），
  这 4 个品类给三边即可报价。bulky 计费 = base 含首 1 lb + $0.38/每 1 lb；
  体积重的宽高各按至少 2 英寸算（官方 FAQ），与标准尺寸口径不同。
- bulky 定档顺序：**先重量（>50 lb 直接超大件）、再长+围（>130 也不大件）、最后三边**。
  59×33×33 三边都没超但长+围 191 → 只看三边会错判。
- 仍缺：超大件整段、2027 的大件（官方重构十档）、服装。费率表现 402 行全 verified
  （标准 378 + 大件 24），H12 的逐格复核范围随之变为 402 格。
- `fee_envelope(weight_ranges_by_tier=...)`：各段按各自上界裁剪。共用一个统一重量范围
  会把大号段的体积重抹掉——不要退回那个写法。

## 总任务与框架锚点（2026-11-23 15:20 锁定 · 讨论任何具体任务前先对齐这一节）

- **总任务**（`docs/00` §1 原文）：把跨境选品决策引擎从个人级 demo 改造成**单人可交付、接近企业级**的项目，
  同时满足简历（大模型/AI 应用开发岗）与面试追问。最终产出是**仓库 + README + 六阶段路线**，
  三条判据：「一条命令复现全部数字」「能回答改了会不会变差」「每个技术取舍能讲清」。
- **框架**（`docs/02` 做什么 / `docs/03` 一个人怎么做）三层：
  - 业务层：评论 → 机会主题 → 合规/成本/毛利 → GO/NO-GO → 反解采购上限（P2，当前所在层）
  - 平台层：10 个必须模块 = 契约抽取 / 评测集 / 持久化 / 任务化 / 幂等 / 鉴权配额 /
    版本三元组 / 利润模型 / 合规表 / 迁移
  - 证据层：`make check` = 测试 + 迁移往返 + 评测 + 基线 diff，退化即非零退出
- **「企业级」不指架构重，指四条约束**：异步任务、幂等提交、参数溯源、版本三元组。
  降级原则：**降规模能力，不降正确性保证**（`docs/03` §5）。
- **阶段判据**：P1 删库能一键重建；P2 陌生 ASIN 能说做不做/为什么/赚多少；
  P3 断网/重启/重复提交账都对得上；P4 干净机器三条命令跑起来。
- **谈价与开口价是 P2 的最后一公里，不是项目终点。** 判断项目完成看 P0–P5 判据，不看单台结论。
