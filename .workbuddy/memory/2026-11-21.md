## 聚类侧扩标：216 条 / 77 簇 / 354 对，阈值 0.65 → 0.72

**先说结论**：阈值从 0.65 改成 **0.72**（ARI 0.240 → 0.357，bootstrap CI [0.68,0.74]）。
但用户原定的「收紧到小数点后两位」**没达成，原因是方法上限而非标注量**——这个负面结论
比阈值本身值钱，已写进 `docs/05` 第 7 节。

**三处结构变更，每处都是被数据逼出来的**：

1. **标注单位：下标对 → 主题簇**。`SAME_PAIRS` 的 (label,a,b) 成本 O(n²)，且新增一条 evidence
   会在组内新增 k 对，默认判成「不同主题」——若其实是同主题就是凭空造出漏检，F1 只轻微下降不报警。
   改成每条 evidence 归属一个簇后 O(n)，pairs 无损派生。**验证过等价：反推 23 簇再派生回 120 对，逐对零差异。**

2. **标注粒度：粗簇 → 部件级**。三种粒度实测（`build_quality` 31 条）：
   粗簇 ARI 0.460 但 gold 只有正/负两组（**聚类按极性分就满分，零区分力**）；
   部件级 0.173；部件×失效 0.182（多数单例不可学）。选部件级。
   v1 的 `flimsy_build` 把「连接器裂/内部松/盖扣不紧/有毛刺」塞一簇，违反它自己声明的规则。

3. **分组口径：label → (dataset,label,polarity)**。生产 `analyze_reviews` 一次只处理一个 dataset。
   导火索是 label 跨品类**语义漂移**：`charging_speed` 在无线充=充电慢、咖啡机=出水慢、
   电水壶=烧水慢、扫地机=吸力弱。代价：v1 的 23 对跨品类对退出，**v1 0.65 与 v2 0.72 不可直接比**。

**关键数字**：
- evidence 51 → 216（6 品类；新 165 条由 live 抽取产出，旧 51 条原样保留）
- 主题簇 77 个；pairs 120 → 354 对（53 组，平均 4.1 条/组，同 125 / 异 229，正例 35.3%）
- v3@512：同主题 P10 0.623 / P50 0.729；不同主题 P90 0.728 / P50 0.648；分离度 **−0.104**
- 阈值 0.72：ARI 0.357 / P 0.580 / R 0.640 / 簇数 120（gold 117）
- bootstrap 2000 次重采样 53 组：P2.5 0.68 / P50 **0.72** / P97.5 0.74，[0.68,0.76] 覆盖 98%
- **v4@1024 比 v3 更差**（分离度 −0.137，ARI 0.343）——换大模型不是解法
- **「充电快」vs「充电慢」相似度 0.872**，全是数据里最高的跨极性对 → 极性必须进分组键

**负面结论（最重要）**：单阈值向量聚类做不到细粒度机会点归并。
同主题 P10（0.623）比不同主题 P90（0.728）低 0.104；阈值 0.70→0.80 簇数从 107 跳到 182，
中间无平滑工作点；把 31 条交给 qwen-plus 一次归并，它输出**重叠分组**（「外壳裂+塑料感廉价」
同时落进两个主题）并漏 1 条。**「一条 evidence 只属于一个主题」粗粒度成立、细粒度不成立。**
要继续做细粒度应换方法（向量粗筛 + LLM 精归并并强制单标签）。

**中途两次自我纠正（值得记）**：
- 先用「组内跨极性对」作负例算出分离度 −0.161，据此判「方法失效」——**错了**。
  生产分组键含 polarity，跨极性对根本不会进同一组。用 `(label,polarity)` 重算才是正确场景。
- 以为 v3 的 0.65 仍是最优，实测 0.72 才是；0.65 落在 bootstrap CI 之外。

**工程改动**：`config.py` dashscope 0.65→0.72、hash 0.12→0.14；`calibrate_cluster.py` 改生产
分组口径 + 三向量对照；新增 `cluster_themes_v2.py`（77 簇 + 216 条逐条归属，单一事实源）、
`extend_cluster_evidence.py`（只追加不改旧数据）；删除 `make_cluster_pairs.py` 与 `cluster_themes.py`。
文件理顺：主文件去版本号，首轮归档为 `_v1`。守卫测试重写为 11 条。

**表述纪律**：聚类侧标注**未经第二人复核**，`charging_speed` 跨品类处分歧风险最高。

## 收尾聚类议题 + 参数区间护栏 + 官方核实

**重开条件是换方法而不是再扩数据**。

**工程一：参数适用区间（迁移 m0007）**

解决 `docs/04` 已知不足 #3——区间只写在 note 里，售价越界照样静默用错值。

- `cost_params` 加 `applies_min/applies_max` + 表级 `CHECK (min <= max)`
- `require(..., applied_to=)`：越界抛 `ParamOutOfRange`（422，与 `ParamUnverified` 503 分开）；
  **有区间但不传 `applied_to` 同样报错**——「不知道是否适用但照样用」和「确认不适用仍用」后果一样
- 语义是**断言式**不是分段表：UNIQUE(key, market) 决定一行只能一个值，
  分段仍靠模型内部实现，区间只负责「这个值在哪个范围成立」
- 14 条新测试，含边界闭区间、写反区间被 CHECK 拒、`mark_verified` 省略区间表示保留而非清空

**踩坑**：`ALTER TABLE ... RENAME` 会把 `sqlite_master` 里的 DDL 文本重写（表名加双引号），
导致 `schema_fingerprint` 与「从未升级到该版本」的库不一致，`test_downgrade_one_step` 正确报红。
改成「先把旧表 rename 走 → 按原文建新表 → 复制 → drop 旧表」，最终 DDL 与常量逐字一致。

**工程二：官方核实（迁移 m0008）**

只采信官方站点，结论分三层：

| 项 | 结论 | 状态 |
|---|---|---|
| FCC 授权 | 无线充电 = 18.107(c) 的 ISM 设备（RF 能量用于传能，非通信）→ consumer ISM 走 **SDoC** | **verified** |
| FCC ID 标注 | SDoC 不分配 FCC ID、不入库；但含独立蓝牙/Wi-Fi 模块则按 Part 15 走 certification 需 ID | draft（是产品事实，非法规事实） |
| 关税 | HTS 8504.40.95 general **Free**、col2 35%；中国原产 +301 25%（9903.88.03）；IEEPA 两层各 10% | **draft** |

关税不填值的理由：USITC 首页称 2026 HTS Revision 13「reflects recently implemented
additional tariffs under section 301」，**是否覆盖 8504.40.95 未确认**。有效税率在
35%~45%+ 之间摆动，填任一值都静默污染毛利。

**合规结论未变**：仍 `blocked`（2 条 blocker，1 条已核实）。`clear` 要求**全部**规则已核实，
部分核实不等于没问题——这个语义要守住。

**测试调整**：4 个测试原本钉住「4 条规则全 draft」的快照，改成钉不变量
（verified_count / 至少一条未核实 blocker / 只返回已核实项），避免把数据快照当契约。

**状态**：309 passed + 1 xfailed；`make check` EXIT=0（F1 0.6070 未变）；迁移 v8，roundtrip 通过。
