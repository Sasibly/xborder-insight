# 2026-11-19 · 跨境选品决策引擎

## 镜像路径闭环：官方 python:3.13-slim 实跑 17/17

**背景**：昨晚遗留的唯一边界是「容器冒烟只在 MCR devcontainers 上跑过，默认的 `python:3.13-slim` 未实跑」。
用户问「外部阻塞怎么修」，查下来这不是 Docker 配置问题。

**定性（实测）**：`registry-1.docker.io` DNS 正常（解析到 Akamai）、TCP 能连但耗时 6.3s（有重传），
**TLS 握手阶段被打断**；`auth.docker.io` 同样；同期 `mcr.microsoft.com` 0.27s 返回 200。
→ 网络层对 Docker Hub 域名的干扰，不是 `daemon.json` 缺代理/加速器（该文件本来是 `{}`）。
**所以处置方向是「换取值渠道」，不是加代理。**

**关键发现**：AWS **ECR Public 存有 Docker 官方 `library/*` 的副本**，
`public.ecr.aws/docker/library/python:3.13-slim` 就是 `Dockerfile` 默认那个镜像。
实测：多架构索引存在（含 linux/amd64）、拉取 21s、**178 MB**（devcontainers 是 2.47 GB）、
Python 3.13.18 / Debian glibc 2.41。

**结果**：
```
./smoke.cmd --target docker --base-image public.ecr.aws/docker/library/python:3.13-slim
→ 17/17 · EXIT=0（连跑两次，第二次 37s）
16 uid=10001  17 HEALTHCHECK healthy
```
日志留存 `reports/smoke_slim.log`。

**表述纪律（已同步改文档）**：现在可以写「在 Docker 官方 `python:3.13-slim` 上实测通过」，
**不能**写「各发行方均验证」——只验了 slim 与 MCR devcontainers 两处，且都是 amd64。

**改到的文档**：`docs/00`（Docker 实跑节 + 下一步第 1 条 + 问题表第 16 行）、`docs/03`（第 246 行
「未验证」补 11-19 更新）、`README`（冒烟结果抬头 + 「镜像只验了两个发行方」+ 下一步 + 新增
「Docker Hub 被干扰时的取镜像顺序」）。顺手修了 README 下一步里两个都编号 5 的笔误。

**另一个可复用的 ops 结论**（写进 README）：Hub 被干扰时的取镜像顺序是
①`public.ecr.aws/docker/library/<name>:<tag>`（内容与 Hub 一致，首选）②`mcr.microsoft.com`（换发行方）
③第三方加速器（最后手段，不进交付物）。

**状态**：280 passed + 1 xfailed（10.46s）、EXIT=0；docker 冒烟 17/17 两个发行方各一次。

**备注**：用户把三个容器也全停了——本项目冒烟自建镜像+临时容器，**一个外部服务都不需要**，
全关反而是最省内存的跑法。宿主内存当前 6.6 GB 可用，`~/.wslconfig` 的 `processors` 已 2→6。
