## P2 前半：利润模型完成（同日 21:40）

**口径已与用户确认（此后不得再改，改动须同步 docs/02 与 README）**：
1. 不预设供应商报价方式，公式**按贸易术语条件分支**；建站初期默认 FOB，且默认值必须回显 `incoterm_assumed`
2. 关税项**条件生效且必须存在**（原公式缺关税项，已修）
3. 退货损耗**分段归集，禁止单一比率**

**产出**：`domain/incoterm.py`（术语 → 含运费/含关税 的映射表，仅 DDP 两项全含）、`domain/profit.py`（纯函数，不读库/时钟/环境）、`db/migrations/m0003_returns_detail.py`（退货四段参数种子）、`tests/test_profit.py`（26 用例）。

**利润模型结构**：
`落地成本 = 报价 + 头程 + 关税` → `毛利 = 售价 − 落地成本 − 佣金 − FBA − 退货影响` → `breakeven_acos = 毛利/售价`

**退货五段**：退款冲减（退货率×售价）+ 处理费（×每件处理费）+ 退款管理费（×费率×**原佣金**）+ 商品损失（×不可再售比例×报价）+ 头程损失（×沉没比例×**实际计入头程**）。各段基数不同，禁止合并。

**测出的真缺陷（重点，面试素材）**：最初只扣四段费用、收入按 100% 计 → 退货率 100% 算出正毛利 6.89、50% 算出盈利 9.54。根因是**退款从未被扣**，偏差恰为 `退货率 × 售价`。补「退款冲减」后为 −23.10 / −5.45。已用双向断言锁定（修复后亏损 / 摘掉修复项重现 +9.54），并实测注入退化会让 3 条测试变红。

**设计要点**：
- 含税/含运术语下**置零并写 assumptions**，不是"忽略"——静默置零会让「以为算了」与「确实没算」无法区分；误传非零值必发 warning
- 负毛利时 `breakeven_acos = None` + 理由，不返回负数（`−0.20` 会被读成"还有 20% 空间"）
- 未知术语转 `InputInvalid`(422)，不让 ValueError 逃成 500
- 佣金按全额计、未按退货比例退回 → 对退货**偏保守**，已在 assumptions 声明（选择不修）

**踩坑**：`test_downgrade_one_step` 把"回退=删表"硬编码了，m0003 只插数据不建表就红了 → 改为与"从未升级那一步"的参照库比对 schema 指纹 + 参数集合，新增迁移不用改测试。

**状态**：119 passed + 1 xfailed，四层门禁全绿，F1 仍 0.8108；真实库已升 v3，11 项成本参数**已核实 0 项**。下一步 P2 后半：compliance + decision + `POST /v1/decision`，参数不核实则接口恒 503。

## P3 任务化（核心完成）

**迁移 v4**：`jobs` 表（tenant_id / kind / status / idempotency_key / request_fingerprint / payload / result / attempts / max_attempts / worker_id / lease_expires_at / 版本三元组 / usage / 时间戳）；`runs` 加 `job_id` + `attempt` 列。

**三条库级约束**：`UNIQUE(tenant_id, idempotency_key) WHERE key IS NOT NULL`（幂等）；`CHECK (status<>'running' OR lease_expires_at IS NOT NULL)`（running 必有租约）；`CHECK (attempts <= max_attempts)`（重试预算）。另 `UNIQUE(job_id, attempt) WHERE job_id IS NOT NULL`（同一次尝试只记一笔账）。

**新增模块**：`jobs/{models,store,handlers,runner}.py`、`service.py`（决策的唯一实现，同步接口与任务共用）、`versions.py`（版本三元组）、`scripts/jobs.py`（status/list/show/recover/drain）。接口：`POST /v1/jobs`(202)、`GET /v1/jobs`、`GET /v1/jobs/{id}`（含 executions）、`POST /v1/jobs/{id}/retry`。

**四个关键设计**
1. 幂等靠唯一索引：直接 INSERT，撞键后回查；不「先查再插」（并发必漏）。
2. 同键 + 不同请求体 → 409 `idempotency_conflict`（比对规范化 JSON 的 sha256）；返回旧任务会让调用方以为新参数生效。
3. 租约 + 心跳续租（租约 1/3 周期）替代「重启时全量改 queued」——后者在多实例下误杀。`requeue_expired` 预算耗尽判 failed 而非留 running。
4. `jobs` 管排队/幂等，`runs` 管每次执行成本；重试是新 attempt（真的又调了一次模型），但同 attempt 唯一。

**版本号是内容哈希**：`PROMPT_VERSION` / `TAXONOMY_VERSION` = sha256 前 12 位。手写 v1.2 一定会忘记升。

**顺手修**：① `JobRunner(handlers={})` 因 `handlers or HANDLERS` 被静默替换成默认表（改 `is None`）；② 分析任务取数失败时不写 `runs` 台账（改台账先开再取数）；③ `_poll` 需 catch-all，否则库未迁移时轮询协程直接死掉且无日志；④ `/ready` 增加 schema 版本校验（库存在≠库可用）。

**实测**：202 即刻返回 → succeeded；`llm_calls=3 / total_tokens=153 / executions=[attempt 1]`；同键重发 3 次队列仍 1 条；同键换体 409；模拟 kill 后 recover 重新入队由另一 worker 接手，attempts=2。

**负向验证**：短路指纹比对 → 库层 + HTTP 层各红一条，恢复即绿。

**状态**：201 passed + 1 xfailed，四层门禁全绿，F1 仍 0.8108，迁移往返到 v4。**待做**：P3b 鉴权配额（API Key→tenant、日 token 配额 429、限流）、P5 Dockerfile+冒烟+回滚；`jobs.result` 无归档策略。
